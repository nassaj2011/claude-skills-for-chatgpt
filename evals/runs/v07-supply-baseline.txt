A defensible audit workflow:

1. Preserve the current state: archive the manifest, lockfile, CI workflow, and exact commit. Make no updates during the audit.
2. Resolve the dependency graph from the lockfile and produce an SBOM containing names, exact versions, source URLs, hashes, licenses, and dependency paths.
3. Verify integrity and provenance: registry hashes/signatures where available; Git dependencies fixed to a reviewed commit SHA; approved publisher/repository ownership.
4. Analyze install scripts in an isolated environment with network and credentials disabled. Flag downloads, shell execution, environment-variable access, postinstall compilation, and native binaries.
5. Scan the *resolved* graph against an approved vulnerability source when access is authorized. Record database/version/date, affected paths, exploitability, and remediation status—never infer CVEs from package names alone.
6. Review CI actions as dependencies: full-SHA pinning, verified creator/publisher, minimal `GITHUB_TOKEN`/OIDC permissions, restricted secrets exposure, and protected workflow changes.
7. Produce an exception register with owner, rationale, compensating controls, expiry, and review date.
