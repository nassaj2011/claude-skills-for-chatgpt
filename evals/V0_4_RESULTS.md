# v0.4 initial model evidence (exploratory)

## Setup

- Model/agent: `gpt-5.6-terra` through Codex CLI 0.147.0
- Run mode: `--ephemeral --ignore-user-config -s read-only`
- All prompts use **fictional flawed code**. The baseline has the task alone; the candidate has the local skill text prepended. Separate Codex sessions were used.
- No file editing, network or production environment testing was permitted. Raw final model text is preserved in `runs/v04-*.txt` with SHA-256 in the associated JSON files.
- The rubric was authored and scored by the assistant, **not** an independent or blind reviewer; criteria include advanced specialist handoff details.

## Review scores

### Database transaction integrity

- **Baseline 69.2% (9/13):** caught check-then-insert race, missing `state` column and replay/unverified callback.
- **Candidate 100% (13/13):** additionally outlined a crash-before/after-commit failure matrix and expand/backfill/contract migration order.
- No executable code patch was generated by these model calls. A separate hand-authored SQLite reference implementation has 9 executable passing tests.

### Security authorization

- **Baseline 69.2% (9/13):** correctly identified read and delete IDORs, and gave wrong-owner/manager negative cases.
- **Candidate 100% (13/13):** additionally supplied explicit role-resource-action table and identified unreviewed surfaces such as CSRF, rate limiting and audit logging.
- No authenticated HTTP penetration test was conducted. Separate domain-level ownership checks run in the reference implementation.

## Reproduce saved-score comparison

```bash
python scripts/evaluate_skills.py --cases evals/benchmarks/v04-db-criteria.json --baseline evals/runs/v04-db-baseline.json --candidate evals/runs/v04-db-candidate.json --require-real
python scripts/evaluate_skills.py --cases evals/benchmarks/v04-security-criteria.json --baseline evals/runs/v04-security-baseline.json --candidate evals/runs/v04-security-candidate.json --require-real
```

These commands check recorded metadata and raw response hashes; they **do not run the model again**. An evaluator can inspect the raw response and disagree with manually assigned criteria. One prompt per skill is not a statistically valid efficacy estimate.

## Interpretation for the public repository

The additional structured operational detail in these two skill-instructed responses is encouraging. It is **not** evidence that all skills reach 8.5/10, or that the model cannot write insecure code. Publish per-skill success rates only after a sufficiently broad, repeated and independently graded test set.
